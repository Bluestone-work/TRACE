# PSTO 100k checkpoint collision analysis

The source run is the final 20-episode Isaac Sim 6.0.1 evaluation of the
100,000-frame checkpoint:

- Checkpoint: `results/psto_p0/long_train_100k/checkpoint.pt`
- Episode CSV: `results/psto_p0/long_train_100k/eval20/episodes.csv`
- Trajectory CSV: `results/psto_p0/long_train_100k/eval20/trajectories.csv`
- Seed range: 50000–50019
- Policy rate: 30 Hz

The rollout reported 14 collision episodes, all classified by the environment
as `pursuer_obstacle_collision`; there were no pursuer-pursuer,
pursuer-evader, or evader-obstacle reports. Five episodes captured and one
episode was a genuine truncation. One CSV row has both the timeout flag and a
terminal collision at the 280-step boundary; it is counted as a collision,
not as a true truncation.

The saved trajectories were reprocessed with:

```bash
conda run --no-capture-output -n trace_isaac \
  python scripts/analyze_psto_collisions.py \
  --out results/psto_collision_analysis
```

Generated files:

- `collision_summary.json`: aggregate counts and evidence limitations.
- `collision_summary.csv`: one row per episode, event timing and minimum pair
  distances.
- `collision_trajectories.csv`: up to 60 policy steps before each event.
- `collision_analysis.md`: machine-generated scope statement.

## What the current evidence proves

The 14 collision labels are not random logging artifacts: they are present in
the real rollout CSV and were generated by the TRACE environment's explicit
collision classifier. The pairwise vehicle distances can be recomputed from
the saved positions, and the trajectory window around each terminal event is
available for inspection.

## What it does not prove

The original recorder did not save PhysX contact impulses, per-step LiDAR
minimum distances, obstacle dimensions, or reward-term vectors. The episode CSV
stores obstacle centers but not the random cuboid scales. Consequently, the
analysis cannot yet prove that every reported obstacle event was a physical
contact rather than a conservative geometric threshold.

The next diagnostic run must log, at every policy step, PhysX contact pairs,
contact normals/impulses, complete obstacle center and scale data, raw and
downsampled LiDAR minima, and the complete reward breakdown. That run should be
used before changing the reward or training curriculum.

## Decision

The evidence is sufficient to block a paper-scale long run and to prioritize
environment/controller calibration. It is not sufficient to claim that the
70% collision rate is caused solely by MAPPO under-training.
